To create a custom Tour Guide dashboard, copy the skill and give it to your LLM. The skill explains how `features/dashboard` supplies the Keystone administration shell while `features/platform` holds the product-specific operator pages.

After that source orientation, it asks what you dislike, what should stay, which workflows and users matter, and what the replacement should look like. It then traces the routes, GraphQL calls, schema, access rules, and sessions before proposing code.

## Current platform routes

Route files live in `app/dashboard/(admin)/platform/**` and stay thin. Each imports one screen.

| Route | Kind | What it does |
| --- | --- | --- |
| `/dashboard/platform/today` | Purpose-built | Today's departures, staffing and waiver alerts, capacity, complete, cancel, Run daily check |
| `/dashboard/platform/calendar` | Purpose-built | Week grid of departures, Put next 60 days on sale |
| `/dashboard/platform/bookings` | Purpose-built | Status tabs, phone and walk-up booking, move, change party, reset guest link, refunds and approvals |
| `/dashboard/platform/waitlist` | Purpose-built | Waiting guests and held offers, phone callers, book for cash |
| `/dashboard/platform/my-departures` | Purpose-built | The signed-in guide's accepted departures |
| `/dashboard/platform/check-in` | Purpose-built | Mobile manifest, check-in (queued offline), no-show and undo, on-site waiver |
| `/dashboard/platform/pickup`, `/dashboard/platform/pickup-day` | Purpose-built | Printable pickup sheets |
| `/dashboard/platform/pricing` | Purpose-built | Seasonal pricing rules |
| `/dashboard/platform/gift-cards` | Purpose-built | Issue, find, reveal and void gift cards |
| `/dashboard/platform/guides` | Purpose-built | Roster, certifications, offer assignment, accept or decline |
| `/dashboard/platform/weather` | Purpose-built | Weather-cancelled departures: rebook or refund each guest |
| `/dashboard/platform/reports` | Purpose-built | Sales report and CSV export |
| `/dashboard/platform/tours` | Generic list | `Tour` |
| `/dashboard/platform/waivers` | Generic list | `WaiverTemplate` |
| `/dashboard/platform/promo-codes` | Generic list | `PromoCode` |
| `/dashboard/platform/resources` | Generic list plus assignment | `Resource`, and assigning vehicles, boats and equipment to upcoming departures |
| `/dashboard/platform/channels` | Purpose-built | Resellers, Generate statement, Record paid |
| `/dashboard/platform/customers` | Purpose-built, read-only | Guests from the latest 500 bookings |
| `/dashboard/platform/settings` | Purpose-built | Operator name, timezone, address, tax, refund approval threshold, waitlist offer window |
| `/dashboard/platform/store` | Purpose-built | Store logo icon, color and SVG |

Sidebar entries come from `features/platform/lib/navigation.ts`. Other routes are the shared shell: `/dashboard/init`, `/dashboard/signin`, `/dashboard/signup` (only with `PUBLIC_SIGNUPS_ALLOWED=true`), `/dashboard/reset`, `/dashboard/no-access`, and the generic `/dashboard/[listKey]` screens, such as `/dashboard/payment-providers` for `PaymentProvider`.

## Named operations

Operator screens call GraphQL through server actions in each slice's `actions` folder.

| Slice | Operations |
| --- | --- |
| today | `departuresInRange`, `resizeDeparture`, `closeDeparture`, `cancelDeparture`, `weatherCancelDeparture`, `sweepDepartures` |
| calendar | `departuresInRange`, `generateDepartures` |
| bookings | `bookings` (generated list), `createChannelBooking`, `operatorBookingByKey`, `bookingMoveOptions`, `moveBooking`, `bookingParty`, `bookingPartyQuote`, `changeBookingParty`, `resetGuestLink`, `requestRefundApproval`, `approveRefund`, `refundBooking` |
| waitlist | `waitlistBoard`, `addToWaitlist`, `bookWaitlistOffer`, `withdrawWaitlistEntry` |
| check-in | `departureManifest`, `departuresInRange`, `checkInParticipant`, `markNoShow`, `undoNoShow`, `syncOfflineCheckIns`, `participantWaiver`, `captureWaiverOnSite` |
| guide-day | `myDepartures`, `pickupSheet`, `dayPickupSheet` |
| guides | `guides` (generated list), `assignGuide`, `respondToAssignment` |
| pricing | `savePricingRule`, `removePricingRule` |
| gift-cards | `giftCardBoard`, `issueGiftCard`, `revealGiftCardCode`, `voidGiftCard` |
| weather | `rebookWeatherBooking`, `refundBooking` |
| reports | `salesReport`, `exportSalesCsv` |
| settings | `updateStoreSettings` |
| onboarding | `ensureTourOnboardingRecord`, `seedTourActivity`, `updateActiveUser` |

The sidebar brand and setup card read `operatorName` and `tourTotal`.

## Notes for a separate dashboard

- Use the custom operations for departures, bookings, refunds, staffing, and check-in. Generated create, update, and delete on those lists are blocked.
- Re-check permission on the server. The pages do not guard by role.
- There is no tenant scope to pass. Every staff user with a flag sees the whole operator.
- Several jobs have no screen yet: offering guides, assigning vehicles, phone booking, approving refunds, resizing a departure, and statements. A separate client can add them on top of the operations in the [GraphQL API](/docs/openfront/tour-guide/api-reference).
