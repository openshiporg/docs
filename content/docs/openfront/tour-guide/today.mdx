`/dashboard/platform/today` lists each departure that starts today in the operator's time zone from [Settings](/docs/openfront/tour-guide/settings). It needs `canCheckIn` because it reads the departure list that guides use.

## What a card shows

- Tour name, start and end time, and the departure status.
- **Seats**: booked seats over capacity. Held seats are shown separately and do not count as booked.
- **Guides**: accepted guides over the guides needed.
- **Held**: seats in unexpired holds.

Guides needed is the booked seats divided by the tour's guests-per-guide ratio, rounded up. The ratio is shown, not enforced. A departure that has bookings but too few accepted guides shows "Not staffed". A departure with unsigned waivers shows how many are missing. A departure in `min_not_met` shows "Minimum not met".

## Actions

- **Manifest** opens the [check-in](/docs/openfront/tour-guide/check-in) page for that departure.
- **Set capacity** (`resizeDeparture`). Capacity cannot go below booked and held seats or above the tour maximum.
- **Complete departure** (`closeDeparture`) for every ended departure the server can complete. Draft guide payouts are created.
- **Cancel departure** opens a popover with two choices. **Weather cancel** takes a weather reason and calls `weatherCancelDeparture`; see [Weather cancellations](/docs/openfront/tour-guide/weather). **Operator cancel** calls `cancelDeparture`. Both need `canManageDepartures`. See [Cancel a departure](/docs/openfront/tour-guide/how-to-guides/cancel-a-departure).

## Run daily check

**Run daily check** runs `sweepDepartures`. It raises minimum alerts for short departures, closes departures past the cutoff, releases lapsed holds, and makes due waitlist offers. It reports each count. There is no scheduler, so press it once a day.

## Notes

The page reads `departuresInRange`. That query allows at most 31 days.
