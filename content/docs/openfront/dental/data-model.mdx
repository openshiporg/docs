## Lifecycles

| List | Statuses |
| --- | --- |
| `Appointment` | `planned`, `scheduled`, `confirmed`, `arrived`, `seated`, `ready_for_checkout`, `completed`, `cancelled`, `broken`, `rescheduled` |
| `Patient` | `prospect`, `active`, `inactive`, `archived`, `deceased`, `merged_into` |
| `ChartEntry` | `diagnosed`, `planned`, `accepted`, `scheduled`, `completed`, `posted`, `existing_current`, `existing_other`, `referred_out`, `refused`, `deleted_in_error`, `corrected` |
| `TreatmentPlan` | `draft`, `presented`, `partially_accepted`, `accepted`, `declined`, `in_progress`, `completed`, `superseded`, `archived` |
| `Claim` | `draft`, `scrubbed`, `ready`, `released`, `submitted`, `submission_unknown`, `acknowledged`, `rejected`, `pending_payer`, `adjudicated`, `correction_required`, `void_requested`, `voided`, `appealed`, `appeal_decided`, `responded`, `closed` |
| `Remittance` | `received`, `parsed`, `matched`, `posting`, `posted`, `reconciled`, `exception`, `duplicate` |
| `Payment` | `initiated`, `requires_action`, `succeeded`, `failed`, `unknown`, `partially_refunded`, `refunded` |
| `Statement` | `generated`, `sent`, `paid`, `partially_paid`, `overdue`, `payment_plan`, `collections_hold`, `suppressed` |
| `PatientMembership` | `pending_agreement`, `active`, `past_due`, `frozen`, `cancelled`, `expired` |
| `LabCase` | `draft`, `sent`, `in_production`, `shipped`, `received`, `qc_passed`, `seated`, `remake_requested`, `cancelled` |
| `Proposal` | `proposed`, `validated`, `invalid`, `approved`, `rejected`, `expired`, `executing`, `executed`, `failed`, `unknown` |
| `ApprovalRequest` | `pending`, `approved`, `rejected`, `expired`, `cancelled` |

Status fields cannot be updated through the generic API. Only the named mutations move them, and each move writes an audit event.
