| Script | Effect |
|---|---|
| `npm run build` | `keystone build --no-ui && next build`; does not migrate |
| `npm run migrate` | `prisma migrate deploy` (creates row-level security policies, so the database role must be one you control) |
| `npm start` | `next start` |
| `npm run validate:env` | Checks `DATABASE_URL` and a 32+ character `SESSION_SECRET` |
| `npm run verify:audit`, `verify:migrations`, `verify:retained-upgrade` | Audit-chain and migration checks; migration checks need disposable databases (`MIGRATION_SHADOW_DATABASE_URL`) |

```bash
npm run build
npm run migrate     # against a backed-up database
npm start
```

There is no worker process. Settlement runs when a result is approved, inbound events are processed on receipt, and audit anchoring advances on `/api/ready`.

## Production environment

Set `DATABASE_URL`, `SESSION_SECRET` (32+ characters), `PUBLIC_APP_URL` (the storefront origin), `CUSTOMER_IDENTITY_SECRET` (32+; derived from `SESSION_SECRET` when unset), `PII_ENCRYPTION_KEY`, `PROVIDER_WEBHOOK_SECRET` for inbound provider events, `OUTBOUND_WEBHOOK_SECRET` and `WEBHOOK_EGRESS_HOSTS` for outbound webhooks, `AUDIT_ANCHOR_DIR` (or a Railway volume) and `AUDIT_ANCHOR_SECRET` for anchoring, `METRICS_BEARER_TOKEN` for probes, SMTP for recovery emails, and the Stripe or Authorize.net variables for card deposits.

## Health

- `/api/health` returns `ok` with the service name and time.
- `/api/ready` checks the database, shipped migrations, row-level security coverage, audit anchoring lag, and privileged operators without MFA, and advances anchoring when it is configured. Detail needs `METRICS_BEARER_TOKEN` in production.
- `/api/metrics` returns Prometheus text (wagers, provider connections, incidents, markets, journal imbalance) and 404s without the bearer token in production.

## After deploy

Create the first operator at `/dashboard/init`, enrol two-factor, run onboarding, and create the independent approver. See [Getting started](/docs/openfront/sportsbook/getting-started).
