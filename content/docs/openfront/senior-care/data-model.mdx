## Lifecycles

| List | Statuses |
| --- | --- |
| `Stay` | `pre_admit`, `admitted`, `discharged`, `deceased` |
| `Bed` | `available`, `reserved`, `occupied`, `held`, `cleaning`, `out_of_service` |
| `Apartment` | `available`, `reserved`, `occupied`, `turnover`, `out_of_service` |
| `Lead` | `new`, `contacted`, `tour_scheduled`, `toured`, `assessment_scheduled`, `assessed`, `deposit_received`, `move_in_scheduled`, `moved_in`, `waitlisted`, `nurture`, `lost` |
| `WaitlistEntry` | `active`, `offered`, `accepted`, `declined`, `expired`, `converted`, `withdrawn` |
| `ProgressNote` | `draft`, `signed`, `amended`, `entered_in_error` |
| `Order` | `active`, `discontinued`, `completed`, `entered_in_error` |
| `AdministrationSlot` | `scheduled`, `given`, `held`, `refused`, `missed`, `not_given` |
| `Incident` | `reported`, `under_investigation`, `closed`, `entered_in_error` |
| `MdsAssessment` | `in_progress`, `completed`, `exported`, `accepted`, `rejected`, `superseded`, `entered_in_error` |
| `Claim` | `draft`, `validated`, `released`, `submitted`, `accepted`, `rejected`, `paid`, `partially_paid`, `denied`, `appealed`, `finalised`, `cancelled` |
| `Statement` | `issued`, `paid`, `void` |
| `Payment` | `pending`, `unknown`, `succeeded`, `failed` |
| `TrustTransaction` | `pending_signature`, `posted`, `rejected` |
| `Shift` | `open`, `filled`, `in_progress`, `completed`, `cancelled` |
| `Credential` | `pending_verification`, `verified`, `expiring`, `expired`, `revoked`, `suspended` |
| `Timecard` | `open`, `submitted`, `approved`, `exported` |
| `ComplianceClock` | `open`, `satisfied`, `overdue`, `satisfied_late`, `waived`, `cancelled` |
| `ApprovalRequest` | `pending`, `approved`, `rejected`, `expired`, `cancelled` |

Status fields cannot be updated through the generic API. Only the named mutations move them, and each move writes an audit event.
