Openfront UIKit is a storefront and registry for one studio's shadcn-compatible component source. Visitors browse components and kits. Signed-in customers unlock free items or buy paid ones, then pull source files with a registry API key. Operators author drafts, validate them, review and publish releases, and manage orders, payments, refunds, entitlements, and keys.

- Source: [github.com/openshiporg/openfront-uikit](https://github.com/openshiporg/openfront-uikit)
- Live site: [uikit.openship.org](https://uikit.openship.org)
- Setup: [Getting started](/docs/openfront/uikit/getting-started)

## Stack

Next.js 16 (App Router, React 19), Keystone 6 with a GraphQL API at `/api/graphql`, PostgreSQL through Prisma 6, Tailwind CSS 4. Sessions are Keystone stateless cookie sessions that last 30 days.

## One studio per deployment

There is no organization, team, or store tenant model. Catalog, release, and design-system records are global. Customer records are scoped to the signed-in user through `Order`, `Payment`, `KitAccess`, and `RegistryApiKey`.

## Main workflows

**Release lifecycle.** An operator creates a draft for a product, edits files, and runs validation. Validation executes the draft in an isolated environment and stores a `ComponentValidation` record. The operator submits for review, a reviewer approves or requests changes, and the release is published as `stable`. Stable releases can later be deprecated. See [Studio](/docs/openfront/uikit/studio) and [Releases](/docs/openfront/uikit/releases).

**Checkout.** A signed-in customer starts a checkout for one product. Free products unlock at once. Paid products go through Stripe or PayPal, and the provider webhook settles the order and grants access. See [Storefront](/docs/openfront/uikit/storefront) and [Payment providers](/docs/openfront/uikit/payment-providers).

**Registry delivery.** A customer creates a registry key at `/account/token`, then installs with the shadcn CLI or the Openfront CLI. See [Registry and CLI](/docs/openfront/uikit/registry-cli).

**Refunds and revocation.** Operators refund captured payments, reconcile pending refunds, and revoke access. These write `AuditEvent` and `OutboxEvent` records. See [Payments and refunds](/docs/openfront/uikit/payments-refunds).

## Integrations

- **Payments**: Stripe Checkout Sessions, PayPal Orders v2, and a manual provider for operator-recorded payments. See [Payment providers](/docs/openfront/uikit/payment-providers).
- **Email**: password reset email through SMTP.
- **AI assistant**: the dashboard chat at `/api/completion` uses OpenRouter (`OPENROUTER_API_KEY`, `OPENROUTER_MODEL`, optional `OPENROUTER_MAX_TOKENS`) and requires dashboard access. It talks to an MCP endpoint at `/api/mcp-transport/<transport>` that exposes generic tools (`listModels`, `queryData`, `searchModels`, `getFieldsForType`, `lookupInputType`, `createData`, `updateData`, `deleteData`, `modelSpecificSearch`) over the signed-in user's GraphQL session.
- **CLI**: `/openfront-ui.js` serves the registry CLI. See [Registry and CLI](/docs/openfront/uikit/registry-cli).
