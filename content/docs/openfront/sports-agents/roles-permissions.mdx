Roles are records with checkboxes. Manage them at `/dashboard/roles`. Any signed-in user can read roles. Changing them needs `canManageRoles`. Permissions are listed in `features/keystone/access.ts`.

## Permissions

| Flag | Allows |
| --- | --- |
| `canAccessDashboard` | Use `/dashboard` and the dashboard assistant |
| `canManagePeople` | Create and delete users, set roles, change other users' passwords |
| `canSeeOtherPeople` | Read other users |
| `canEditOtherPeople` | Update other users |
| `canManageRoles` | Create, update, delete roles |
| `canManageAthletes` | Athletes, teams, contacts, interactions, tasks, documents |
| `canManageContracts` | Representation agreements, playing contracts, years, incentives, certifications |
| `canManageEndorsements` | Brands, endorsement deals, deliverables |
| `canManageCommissions` | Scheduled payments, invoices, the ledger, agent splits, and payment collections and sessions |
| `canManageTrust` | Client trust accounts and entries |
| `canViewAllClients` | See every athlete, not only assigned ones |
| `canManagePayments` | Read payment providers, payments, refunds, and webhook events. Create or change a provider |
| `canReadPayments` | Read payment providers, payments, and refunds |
| `canIssueRefunds` | Request refund approvals. No refund command exists |
| `canReadAudit` | Read `AuditEvent` rows |
| `canManageOnboarding` | Run setup and read or edit the `Agency` record |
| `canApproveActions` | Approve or reject approval requests |

## Athlete scope

Athletes and the lists that hang off them are filtered. A user sees an athlete only if they are the lead agent or on the support staff, unless the role has `canViewAllClients`. The filter applies to query and update on `Athlete`, agreements, contracts, years, incentives, deals, deliverables, interactions, tasks, documents, scheduled payments, invoices, invoice lines, ledger entries, agent splits, trust accounts, and trust entries.

Commands check the same scope again. A command for an athlete you cannot see returns "Athlete not found".

Lists with no athlete link are not scoped: `Agency`, `AgentCertification`, `Team`, `Contact`, `Brand`, `AuditEvent`.

## Write rules

- Status fields on most lists cannot be set through generated create or update. They change through commands.
- `ScheduledPayment`, `CommissionInvoice`, `CommissionInvoiceLine`, `CommissionLedgerEntry`, `AgentSplit`, `ClientTrustEntry`, `Document`, and `AuditEvent` have no generated create or delete in GraphQL, and their operation access denies generated create and update.
- No list allows generated delete for staff.
- `ManagerApproval` cannot be created or updated through generated GraphQL. Requests and decisions go through commands.

## Seed roles

| Role | Permissions |
| --- | --- |
| Owner | All, including `canApproveActions` |
| Agent | Dashboard, see other people, athletes, contracts, endorsements, read payments |
| Marketing Rep | Dashboard, see other people, athletes, endorsements |
| Accountant | Dashboard, see other people, view all clients, commissions, trust, payments, refunds, audit, approve actions |
| Customer | None. No dashboard |

The first user created at `/dashboard/init` gets an `Admin` role with every permission on. Give other roles only what the job needs, because the assistant and MCP tools act with the same permissions.
