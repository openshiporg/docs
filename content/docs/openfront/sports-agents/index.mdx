Openfront Sports Agents is agency software for sports agents and NIL agencies. Staff track athletes and recruiting, representation agreements, playing contracts, and endorsement deals. The money side follows one rule: commission is earned when the athlete is paid, not when a deal is signed.

It is built on Next.js 16, React 19, Keystone 6 (GraphQL), Prisma, and PostgreSQL.

## Status

- The repository is private. There is no hosted app and no demo.
- Payments run on Stripe in test mode in development. No live payment setup is shipped.
- The public site is a plain placeholder. It has no design yet.
- The docs describe what the code does today.

## Who uses what

| User | Surface | Typical jobs |
| --- | --- | --- |
| Agent | Dashboard | Roster, recruiting, agreements, contracts, deals |
| Marketing rep | Dashboard | Endorsement deals and deliverables |
| Accountant | Dashboard | Payments, invoices, ledger, trust, approvals |
| Owner | Dashboard | Everything, including setup and approvals |
| Brand or athlete | Public site | Send an inquiry, find an invoice, pay it by card |

## Surfaces

- **Dashboard** at `/dashboard`: the money view, clients, recruiting, contracts, endorsements, commissions, trust, approvals, brands, tasks, certifications, payment providers, and settings. See [Dashboard](/docs/openfront/sports-agents/dashboard-money) and [External dashboards](/docs/openfront/sports-agents/external-dashboard).
- **Public site** at `/`: published athletes with an inquiry form, and invoice lookup and payment. See [Public site and invoice payment](/docs/openfront/sports-agents/public-site).
- **GraphQL** at `/api/graphql`. See [API reference](/docs/openfront/sports-agents/api-reference).
- **Payment webhook** at `/api/integrations/payment/[providerCode]/webhook`.
- **Assistant and MCP** at `/api/completion` and `/api/mcp-transport/[transport]`. See [MCP and assistant](/docs/openfront/sports-agents/mcp-assistant).

## Models

The schema has 35 lists in `features/keystone/models`. Money is stored as integer cents. Ledger amounts are `bigInt`. Rates are basis points, so 1% is 100.

| Area | Lists |
| --- | --- |
| Identity | `User`, `Role`, `OAuthApp`, `OAuthToken` |
| Agency | `Agency`, `AgentCertification`, `Team` |
| Clients | `Athlete`, `RepresentationAgreement`, `Contact`, `Brand`, `Interaction` |
| Contracts | `PlayingContract`, `ContractYear`, `Incentive` |
| Endorsements | `EndorsementDeal`, `Deliverable` |
| Money | `ScheduledPayment`, `CommissionInvoice`, `CommissionInvoiceLine`, `CommissionLedgerEntry`, `AgentSplit`, `ClientTrustAccount`, `ClientTrustEntry` |
| Records | `Document`, `Task`, `AuditEvent`, `ManagerApproval`, `IdempotencyKey` |
| Payments | `PaymentProvider`, `PaymentCollection`, `PaymentSession`, `Payment`, `Refund`, `PaymentWebhookEvent` |

Money lists are not writable through generated create, update, or delete. They change only through custom mutations. See [Data model](/docs/openfront/sports-agents/data-model).

## One agency per deployment

There is one agency per deployment. The `Agency` list holds its settings. There is no organization or tenant model. Client visibility is scoped by assignment instead. See [Roles and permissions](/docs/openfront/sports-agents/roles-permissions).
