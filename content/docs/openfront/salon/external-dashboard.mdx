---
title: External dashboards
description: Give an LLM the Salon dashboard skill to adapt the built-in experience or create a separate client.
---

To create a custom Salon dashboard, copy the skill and give it to your LLM. The skill will explain how `features/dashboard` supplies the Keystone administration shell while `features/platform` contains Salon's product-specific operator experience.

After that source orientation, it will ask what you dislike, what should stay, what workflows and users matter, and what the replacement should look and feel like. It then traces the exact routes, feature slices, GraphQL calls, schema, access rules, sessions, and provider boundaries in the supplied Salon codebase before proposing work.

## Current platform routes

Route files live in `app/dashboard/(admin)/platform/**` and stay thin. Each one wraps a screen from `features/platform` with `withPlatformPermission`. A user with `canManageSalon` passes every check. Otherwise the role needs at least one listed flag, or the page redirects to `/dashboard/no-access`.

## Notes for a separate dashboard

- Use the custom mutations for bookings, checkout, refunds, payouts, benefits, gift cards, stock, and schedules. The generated create, update, and delete for those lists are blocked.
- Re-check permission on the server. The page guards in `withPlatformPermission` only control navigation.
- Consultation answers need `canManageCareRecords`. The manager flag does not grant it.
- There is no tenant scope to pass. Every staff user with a flag sees all locations.
