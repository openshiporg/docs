| Script | Effect |
|---|---|
| `npm run build` | `keystone build --no-ui && next build`; does not migrate |
| `npm run migrate` / `npm run release:migrate` | `prisma migrate deploy` |
| `npm start` | `next start` |
| `npm run lint` | ESLint |

```bash
npm run build
npm run migrate   # against a backed-up database
npm start
```

The included `railway.toml` builds with `keystone build --no-ui && next build` and starts with `npm run migrate && next start`, because the Railway build environment cannot reach an internal database. The README includes a Vercel import button.

Provision PostgreSQL, S3-compatible storage, SMTP, and payment and shipping credentials. Share the same database, `SESSION_SECRET`, and storage across all application processes.

## Webhook delivery

Outbound webhook events are written to an outbox and attempted with retries. Run the `retryWebhookDeliveries` mutation (or the Webhook events list) on a schedule from your platform's cron to redeliver due events. See [Integrations](/docs/openfront/vape/integrations).

## Behind a proxy

Set `TRUSTED_PROXY_IPS` to the proxies whose `x-forwarded-for` header is trusted for the client IP (used for login history and API key IP restrictions).

## After deploy

Create the first operator at `/dashboard/init`, run onboarding, then follow [Go live](/docs/openfront/vape/how-to-guides/go-live).
