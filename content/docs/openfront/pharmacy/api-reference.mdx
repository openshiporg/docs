The GraphQL endpoint is `/api/graphql`. Generic Keystone queries exist for lists that allow them. The custom operations below are registered in `features/keystone/mutations/index.ts`. Consequential mutations take `reason` and `attested`, and many take an `idempotencyKey`.

## Example: dispense

```graphql
mutation Dispense($prescriptionId: ID!, $prescriptionItemId: ID!, $lotId: ID!) {
  recordPrescriptionDispensing(
    prescriptionId: $prescriptionId
    prescriptionItemId: $prescriptionItemId
    lotId: $lotId
    quantity: 30
    cashReceivedAmount: 1500
    auxiliaryWarnings: ["Take with food"]
    counselingOutcome: "offered_accepted"
    idempotencyKey: "rx-1042-fill-1"
    reason: "Verified label and lot"
    attested: true
  ) { success prescriptionId status }
}
```

Patient-safe and guest projections leave out guest-token hashes, provider credentials, audit metadata, and outbox payloads. Requesting an omitted field fails at the schema.

## HTTP routes

| Route | Purpose |
|---|---|
| `POST /api/graphql` | GraphQL |
| `POST /api/payment-webhooks/[providerId]` | Payment webhooks |
| `POST /api/webhooks/integrations/[providerKey]` | eRx and insurance webhooks |
| `/api/mcp-transport/[transport]` | MCP server |
| `/api/completion` | Dashboard AI chat |
