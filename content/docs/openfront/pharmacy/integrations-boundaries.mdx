A provider record shows a configuration and a validation state. It does not prove that a contract exists, that the provider accepted a request, that money moved, or that a claim was paid.

## Payments

Adapters are registered in `features/integrations/payment/index.ts`: `stripe`, `paypal`, and `manual`. A `PaymentProvider` record picks an adapter by name in its `*Function` fields. It must be installed (`isInstalled`) before it is offered at checkout.

| Adapter | What the code does |
|---|---|
| `stripe` | Creates, captures, refunds, and reads PaymentIntents with `STRIPE_SECRET_KEY`. Verifies webhooks with `STRIPE_WEBHOOK_SECRET`. The storefront card step needs `NEXT_PUBLIC_STRIPE_KEY` |
| `paypal` | Server-side order create, capture, refund, status, and webhook verification using `NEXT_PUBLIC_PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET`, `PAYPAL_WEBHOOK_ID`, and `NEXT_PUBLIC_PAYPAL_SANDBOX`. The storefront has no PayPal approval step |
| `manual` | "Pay at pickup". No money moves online. Rejects webhooks. Payment is collected at handoff |

Onboarding creates "Pay at pickup" (installed) and, in the full template, "Stripe" (not installed). You install or uninstall providers on `/dashboard/platform/payments`.

Payment webhooks go to `POST /api/payment-webhooks/[providerId]`. The route limits the body to 1 MB and passes the raw body to `handlePaymentProviderWebhook`. That mutation checks the provider signature, then the amount and currency against the stored payment. It handles succeeded and refunded events. Sessions that end up paid without an order, or that need a refund, are listed under "Needs reconciliation" on the Payments page. Staff resolve them with `reconcilePharmacyPaymentSession`.

Cash: `recordPharmacyCashPolicy` stores a tax rate in basis points and a policy reference. POS sales and prescription dispensing use that rate. Online cart tax is 0.

## eRx and insurance

`features/integrations/erx/index.ts` and `features/integrations/insurance/index.ts` each register one adapter, `manual`. It is a generic HTTP client configured per provider:

- `configurePharmacyIntegrationProvider` stores a base URL, validation, submit, and status paths, a bearer token (at least 16 characters), and a webhook secret (at least 32 characters). eRx also needs a prescriber validation path containing the `{npi}` placeholder. It calls the validation path. If that works, it marks the provider `active` and `externalValidationComplete`. Only `erx` and `insurance` providers can be configured.
- Production endpoints must use HTTPS. Responses are size-bounded, and requests time out after 20 seconds.
- `validatePharmacyPrescriber` calls the eRx prescriber path for a prescriber's NPI.
- `submitPharmacyExternalWorkflow` sends a prescription (eRx) or an order (insurance) to the submit path with an idempotency key. `refreshPharmacyExternalWorkflow` reads the status path.
- Inbound webhooks go to `POST /api/webhooks/integrations/[providerKey]`. The adapter checks an HMAC-SHA256 of the raw body in the `x-pharmacy-signature-sha256` header.

The platform pages call `configurePharmacyIntegrationProvider` and `validatePharmacyPrescriber`. No page calls `submitPharmacyExternalWorkflow` or `refreshPharmacyExternalWorkflow`.

The request and response shapes are the app's own. They are not a certified eRx network (for example SCRIPT) or a standard payer transaction. You need a provider-side service that speaks this contract.

## Wholesaler and tax

Onboarding creates "Wholesaler" and "Tax" integration records with status `unconfigured`. No wholesaler or tax adapter exists, and the configure command refuses those types. Suppliers are local records. Lots are received by hand.

## Outbox

Each command writes an `OutboxEvent` in the same transaction as its state change. The Audit page shows the outbox timeline. `replayPharmacyOutboxEvent` (needs `canManageIntegrations`) resets a `failed` or `dead_letter` event to `pending`. The repository has no worker that delivers outbox events, so events stay `pending` unless you build one.

## Email and storage

SMTP settings are used for password-reset email. The app sends no order, refill, or patient notifications. S3 storage is configured for Keystone image fields. No prescription document upload exists.

## MCP and AI

- `/api/mcp-transport/[transport]` is an MCP server that only answers callers whose session has `canAccessDashboard`. Its tools are generic GraphQL tools: `listModels`, `queryData`, `searchModels`, `getFieldsForType`, `lookupInputType`, `createData`, `updateData`, `deleteData`, and `modelSpecificSearch`. They run with the caller's own session, so list access rules still apply. Pharmacy commands have no dedicated tools.
- `/api/completion` is the dashboard AI chat. It needs `canAccessDashboard`, and uses `OPENROUTER_API_KEY` and `OPENROUTER_MODEL`, or a key the user supplies in the browser.

<Callout type="warn">
Do not send patient or prescription data to an AI model without a privacy review. An agent must not approve, dispense, release stock, or report that a provider accepted something.
</Callout>
