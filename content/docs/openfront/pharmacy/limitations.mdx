## Missing or partial in the code

- **Cold chain.** `receivePharmacyInventoryLot` rejects cold-chain lots, and the receive form says so. `recordTemperatureExcursion` exists but is not in the GraphQL schema. No command releases or destroys an excursion. Excursion rows show on the lot page but cannot be created from the app.
- **Controlled substances.** Intake and dispensing need a drug reference review with schedule `none`. Controlled drugs cannot go through the workflow at all. There is no EPCS, PDMP, or controlled-substance log.
- **Prescription dispensing tender.** `recordPrescriptionDispensing` records a cash payment only. Card or insurance payment for a dispensed prescription is not supported.
- **Online tax.** Cart and online order tax is always 0. Only POS sales and dispensing apply the organization's cash tax rate. No tax service is connected.
- **Delivery.** Locations have a delivery switch and orders have delivery addresses. There are no delivery fees, couriers, or proof of handoff beyond the staff transition. Onboarding turns delivery off.
- **PayPal checkout.** The PayPal adapter exists on the server, but the storefront has no PayPal approval step.
- **Wholesaler and tax integrations.** These are placeholder records with status `unconfigured`. No adapter exists for them.
- **eRx and insurance.** One generic HTTP adapter with an app-defined contract. It is not a certified eRx network or payer connection. No page calls `submitPharmacyExternalWorkflow` or `refreshPharmacyExternalWorkflow`.
- **Outbox delivery.** No worker delivers outbox events. The README lists `npm run worker:outbox`, but `package.json` has no such script.
- **Machine credentials.** The `MachineCredential` list exists, but nothing issues, rotates, or authenticates these tokens.
- **Notifications.** Email is used only for password reset. There are no order, refill, or recall messages to patients.
- **Customer self-service.** Customers cannot cancel orders, request a transfer out, or link their own patient profile. Staff link the account with `linkPharmacyPatientAccount`.
- **Storefront host.** Store settings does not edit `storefrontHost`. Onboarding sets it from the request host.
- **Checks.** `package.json` has no `test` or `typecheck` script, though the README lists both. The `tests/` folder holds two `.cjs` files.

## Work that stays with people

The software records role checks, reasons, attestations, and approvals. It cannot tell whether a person is licensed, working within scope, or making a sound clinical decision. Drug use review, substitution rules, counseling, prescriber contact, identity checks, and physical verification stay with the pharmacist.

Staff and prescriber credential reviews store the evidence the operator types in. The app does not check any licensing or NPI registry, unless you set up eRx prescriber validation against a provider.

Recall exposure rows come from local dispense and sale movements. The app does not get recall notices from the FDA or manufacturers, and does not send outreach.

## Privacy and security

Tenant filters and limited projections reduce what each user sees. The code does not provide field encryption, managed key rotation, centralized audit monitoring, breach response, patient data export, or retention jobs. Do not load real patient, prescription, or payment data until the full data flow has been reviewed.

## Release process

`npm run dev` applies migrations to the database in `DATABASE_URL`. `npm run build` does not. Run migrations as a separate, backed-up step. Test cross-organization and cross-location access, wrong-role access, concurrent dispensing and checkout, duplicate webhooks, and rollback against your own PostgreSQL before you deploy.
