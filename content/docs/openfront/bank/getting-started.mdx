## Requirements

- Node.js 20 or later
- PostgreSQL, with an administrator able to create a login role

import { Step, Steps } from 'fumadocs-ui/components/steps';

<Steps>
<Step>

### Clone and install

```bash
git clone https://github.com/openshiporg/openfront-bank.git
cd openfront-bank
npm install
```

</Step>
<Step>

### Configure `.env`

```bash
cp .env.example .env   # DATABASE_URL, SESSION_SECRET, BANK_SECRET_KEY
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"   # a BANK_SECRET_KEY
```

| Variable | Notes |
| --- | --- |
| `DATABASE_URL` | The web process connection: a login in the DML-only `bank_app` role. Required. |
| `MIGRATE_DATABASE_URL` | The owner connection, used only by `npm run migrate`. Leave unset locally to migrate with `DATABASE_URL`. |
| `SESSION_SECRET` | Signs staff and customer sessions. 32 or more characters. Required. |
| `BANK_SECRET_KEY` | Encrypts SecretBox and PII. 32 bytes, base64url. Rotate with `BANK_SECRET_KEY_V2` and `BANK_SECRET_KEY_VERSION=2`. Required. |
| `BANK_SEED_ADMIN_PASSWORD` | At seed time, the password (12 or more characters) for the seeded administrator. |
| `BANK_PUBLIC_URL` | The public base URL used for partner webhook URLs. Falls back to `NEXT_PUBLIC_SITE_URL`. |
| `BANK_ALLOW_LIVE_PARTNERS` | Leave unset. Partner production hosts are refused unless it is `true` and go-live was approved. |
| `OPENROUTER_API_KEY`, `OPENROUTER_MODEL` | The model used by the dashboard assistant. |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` | Mail for password resets. |

</Step>
<Step>

### Apply migrations and start

The web process never connects as the table owner. Migrations create a NOLOGIN group role `bank_app` with data access only. Create a login in it once, as an administrator:

```sql
CREATE ROLE bank_web LOGIN PASSWORD '…' IN ROLE bank_app;
ALTER ROLE bank_web INHERIT;
```

Set `DATABASE_URL` to that login and `MIGRATE_DATABASE_URL` to the owner. Then:

```bash
npm install
npm run migrate
npm run dev
```

Partner keys, such as Plaid, are not environment variables. An administrator enters them on **Institution → Partners and lists**, and they are sealed.

</Step>
<Step>

### Create the first user

Open `/dashboard/init` and create the first user. Its role, **Owner / Admin**, gets every permission except break-glass.

</Step>
<Step>

### Load the sample institution

Choose **Load Harbor Pine Community Bank** in the dashboard to load a complete fictitious institution in one section, **Institution, people and controls**.

| What it loads | Detail |
|---|---|
| Institution | Harbor Pine Community Bank, N.A., a national bank in settlement mode A (chartered core), America/New_York, with a 20:00 cutoff. |
| Branches | Harbor Street (main office), Pine Ridge and Millbrook. |
| Programs | Harbor Pine Retail, Harbor Pine Business and the sponsored fintech program Ledgerly. |
| People | Roles with separated duties and staff, including the administrator Ayesha Rahman (`ayesha.rahman@harborpinebank.example`). |
| Time and rails | The Federal Reserve calendar 2025-2031 and the FedACH and Fedwire rail windows. |
| Controls | Dated regulatory parameters and the maker-checker approval policies. |
| Products and partners | Everyday Checking, High-Yield Savings and Business Checking, and the in-house FedACH, identity review, OFAC and FinCEN connections, with Plaid on test keys. |

Set `BANK_SEED_ADMIN_PASSWORD` when seeding and Ayesha Rahman can sign in at once. Otherwise every seeded person waits for a password reset. There is no default password.

</Step>
</Steps>

## Tests

```bash
npm run typecheck
npm run lint
BANK_TEST_DATABASE_URL="postgres://…/db?schema=vitest" npm test
npm run test:node
```

Database tests run only when `BANK_TEST_DATABASE_URL` names a `vitest` schema, and the suite truncates that schema. To run them as the application would, point it at a `bank_app` login and `BANK_TEST_OWNER_DATABASE_URL` at the owner.
