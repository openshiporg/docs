Access is permission-based. A role is a set of boolean permission flags on `Role`, and every custom mutation checks the flag it needs on the server. Flags are defined in `features/keystone/access.ts`. Staff limits cap what a person may do, and approvals always need a different person.

## Permission flags

| Area | Flags |
| --- | --- |
| Starter and fleet-mandatory | `canSeeOtherPeople`, `canEditOtherPeople`, `canManagePeople`, `canManageRoles`, `canAccessDashboard`, `canManageOnboarding`, `canManagePayments`, `canIssueRefunds`, `canReadAudit` |
| Institution and configuration | `canManageInstitution`, `canManageBranches`, `canManageCalendars`, `canManagePaymentsConfig`, `canManageIntegrations`, `canApproveConfig` |
| Programs and treasury | `canManagePrograms`, `canManageTreasury`, `canApproveTreasury`, `canReadTreasury` |
| Products | `canManageProducts`, `canApproveProducts` |
| Parties and KYC | `canManageParties`, `canReviewKyc`, `canApproveHighRisk`, `canReadParties`, `canReadPII` |
| Deposit accounts | `canManageAccounts`, `canPlaceRestrictions`, `canApproveAccountChanges`, `canReadAccounts` |
| Payments | `canInitiatePayments`, `canOperateAch`, `canOperateWires`, `canApprovePayments`, `canReleaseWires`, `canReadPayments` |
| Cards | `canManageCards`, `canApproveCardOverrides`, `canReadCards` |
| Disputes | `canManageDisputes`, `canApproveDisputes` |
| Teller and cash | `canOperateTeller`, `canSuperviseTeller` |
| Lending | `canOriginateLoans`, `canServiceLoans`, `canCollect`, `canApproveCredit`, `canApproveLoanChanges`, `canReadLoans` |
| Accounting and GL | `canManageAccounting`, `canApproveAccounting`, `canReadAccounting` |
| Operations | `canWorkExceptions`, `canReconcile`, `canApproveExceptions`, `canReadOperations` |
| BSA/AML and sanctions | `canWorkAlerts`, `canManageAmlCases`, `canFileCtr`, `canApproveSanctions`, `canApproveSar`, `canReadBsa`, `canAccessSar` |
| Consumer compliance | `canManageCompliance`, `canManageComplaints`, `canApproveCompliance` |
| Statements and tax | `canManageStatements` |
| Data sharing | `canManageDataSharing`, `canApproveDataSharing` |
| Agents | `canManageAgents`, `canApproveAgentGrants` |
| Break-glass (never seeded) | `canBreakGlass` |

## Seeded roles

Loading the sample institution creates these roles.

| Role | What it does |
| --- | --- |
| Administrator | People, roles, institution set-up and integrations. Approves configuration. |
| President/CEO | Reads everything outside the SAR compartment and approves configuration, treasury and high-risk decisions. |
| CFO/Controller | General ledger, manual journals, period close and products approval. |
| Treasury | Liquidity, settlement accounts and program FBO positions. |
| Chief Risk Officer | Risk appetite, exception waivers and recon acceptance. |
| BSA Officer | Owns the BSA/AML programme: SAR decisions, sanctions dispositions, CTRs. |
| BSA Analyst | Works alerts and drafts cases and CTRs. |
| Compliance Officer | Consumer compliance, complaints, disclosures and regulatory parameters. |
| Deposit Operations | Account maintenance, restrictions, dormancy, statements and exceptions. |
| Payments Operations | ACH files, wires, returns and payment exceptions. |
| Card Operations | Card issuing, controls and chargebacks. |
| Branch Manager | Supervises tellers and approves branch overrides and account changes. |
| Teller | Cash deposits and withdrawals within the drawer limit. |
| Universal Banker | Opens accounts and onboards customers. |
| Loan Officer | Takes and works loan applications. |
| Credit Approver | Approves credit within limit. |
| Loan Servicing & Collections | Payments, escrow and collections. |
| Customer Service | Answers customers, logs complaints and Reg E claims. |
| Examiner/Auditor | Read-only and time-boxed by the access expiry. |
| Program Manager | Program staff: reads its own program’s oversight data. |
