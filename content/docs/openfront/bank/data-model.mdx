| Area | Lists |
| --- | --- |

## Lifecycles

| List | Statuses |
| --- | --- |
| `Application` | `draft`, `submitted`, `verifying`, `review`, `approved`, `declined`, `withdrawn`, `expired`, `fulfilled` |
| `DepositAccount` | `pending_funding`, `active`, `dormant`, `escheat_pending`, `escheated`, `closing`, `closed` |
| `DepositProductVersion` | `draft`, `in_review`, `published`, `retired` |
| `Journal` | `posted`, `reversed` |
| `Hold` | `active`, `partially_captured`, `captured`, `released`, `expired` |
| `TransferRequest` | `draft`, `submitted`, `pending_approval`, `scheduled`, `executing`, `completed`, `failed`, `canceled` |
| `AchEntry` | `scheduled`, `pending_review`, `pending_risk`, `approved`, `queued`, `batched`, `submitted`, `unknown`, `acknowledged`, `settled`, `completed`, `returned`, `return_dishonored`, `return_contested`, `rejected`, `canceled`, `reversal_requested` |
| `AchFile` | `building`, `built`, `transmitting`, `ready_to_send`, `transmitted`, `unknown`, `acknowledged`, `rejected`, `received`, `parsed`, `posting`, `posted`, `partially_posted` |
| `AchReturn` | `received`, `matched`, `applied`, `dishonor_pending`, `queued`, `sent`, `settled` |
| `ExternalAccountLink` | `initiated`, `pending_verification`, `verified_low_confidence`, `verified`, `needs_reauth`, `consent_revoked`, `invalid`, `failed`, `removed` |
| `TellerDrawer` | `assigned`, `open`, `balancing`, `closed`, `closed_over_short` |
| `CtrFiling` | `required`, `drafted`, `filed`, `acknowledged`, `rejected`, `amended` |
| `BusinessDay` | `scheduled`, `open`, `cutoff`, `eod_running`, `eod_failed`, `closed` |
| `EodRun` | `running`, `completed`, `failed` |
| `ApprovalRequest` | `pending`, `approved`, `rejected`, `expired`, `cancelled`, `superseded` |

Status fields cannot be updated through the generic API. Only the named mutations move them, and each move writes an audit event.
