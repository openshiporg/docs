The repository includes `railway.toml`. The build runs `keystone build --no-ui && next build`, and the start command runs migrations first. `npm run migrate` uses `MIGRATE_DATABASE_URL` when set.

## Processes

| Process | Command | Purpose |
| --- | --- | --- |
| Web | `npm run migrate && next start` | Applies migrations as the owner, then serves the dashboard, the public website, online banking, webhooks and MCP as the `bank_app` login. |

## Checklist

1. Provision PostgreSQL. Create the `bank_web` login in `bank_app`.
2. Set `DATABASE_URL` to the login and `MIGRATE_DATABASE_URL` to the owner.
3. Set `SESSION_SECRET` and `BANK_SECRET_KEY`.
4. If the migrating role does not own the database, run `REVOKE TEMPORARY ON DATABASE <db> FROM PUBLIC, bank_app` once.
5. Deploy, open `/dashboard/init` and create the first user.

There is no scheduler, timer, cron, outbox or worker. Due jobs run when staff load the dashboard (`runDueWork`, one call per page load) and from staff buttons: **Run end of day** and **Cut off now** on Operations, and **Run ACH cycle now** and **Run due jobs** on ACH. Each job claims a fenced lease, so concurrent loads never run the same job twice.

| Job | Schedule |
|---|---|
| `eod.run` | Every minute |
| `ach.originate` | Every minute |
| `ach.inbound`, `ach.returns`, `ach.settle` | Every 5 minutes |
| `webhooks.process` | Every minute |
| `payments.risk_reports` | Every minute |

`GET /api/health` reports database reachability.
