The schema lives in `features/keystone/models`. Every list has `createdAt` and `updatedAt`. Money is an integer in cents with a currency code (default `USD`). Percentages are basis points (100 = 1%). Lists marked **command only** block generated create, update, and delete. They change only through the custom operations in [API reference](/docs/openfront/comedy-club/api-reference). On the other lists, any state field that moves through a lifecycle (for example `Show.status`, `Run.status`, and `Comedian.status`) cannot be set by generated create or update either. A state change on those goes through a custom operation. `PromoCode.status` is a plain editable field. No show, order, ticket, check, payout, or settlement list allows generated delete. Setup and identity lists are the exception: `User`, `Role`, `OAuthApp`, `OAuthToken`, and `PaymentProvider` can be deleted by the people who manage them.

## Identity

`User` has `name`, `email`, `password`, a `role`, `onboardingStatus`, `notificationPreference`, and links to orders, comps, seatings, checks, check-ins, settlements, and audit events. `Role` holds the permission flags. `OAuthApp` and `OAuthToken` back the MCP sign-in.

## Rules the server enforces

- **Capacity.** Hold, comp, and checkout take a database lock named for the show. Under the lock they check that sold plus held plus the new quantity fits the tier and the show.
- **Idempotency.** Every money or inventory operation takes an idempotency key. Reusing a key with different input is refused. The same key returns the stored answer.
- **Copies at purchase.** Orders, lines, and checks store the price, fees, tax, and rules in force. Later edits to the menu, tiers, or venue do not change them.
- **Compare and set.** Status changes check the current state in the write, so two people acting at once cannot both win.
- **Audit.** State changes write an `AuditEvent`.
