title: External dashboards
description: Give an LLM the Hotel dashboard skill to adapt the built-in experience or create a separate client.
---

To create a custom Hotel dashboard, copy the skill and give it to your LLM. The skill will explain how `features/dashboard` supplies the Keystone administration shell while `features/platform` contains Hotel's product-specific operator experience.

After that source orientation, it will ask what you dislike, what should stay, what workflows and users matter, and what the replacement should look and feel like. It then traces the exact routes, feature slices, GraphQL calls, schema, access rules, sessions, and provider boundaries in the supplied Hotel codebase before proposing work.

Skill file: [`/skills/openfront-hotel-custom-dashboard/SKILL.md`](/skills/openfront-hotel-custom-dashboard/SKILL.md)

## Current platform pages

Routes are `app/dashboard/(admin)/platform/<route>/page.tsx`. Each route file only re-exports a screen from `features/platform/<slice>`. Navigation is defined in `features/platform/lib/navigation.ts`.

Shortcut routes outside `/platform` render the same screens: `/dashboard/reservations`, `/dashboard/housekeeping`, and `/dashboard/guests/[id]`.

Sign-in and setup pages sit outside the admin layout: `/dashboard/init` (first user), `/dashboard/signin`, `/dashboard/signin/mfa`, `/dashboard/reset`, `/dashboard/signup` (closed unless `PUBLIC_SIGNUPS_ALLOWED=true`), and `/dashboard/no-access`. The onboarding dialog is opened from the dashboard layout; its code is in `features/platform/onboarding`.

The dashboard home is `/dashboard`. Lists without a dedicated page (for example `Role`, `User`, `RoomType`, `Booking`) use the generic `/dashboard/[listKey]` list, item, and create pages. Writes there still go through model access rules, which deny direct edits to `Booking`, `ReservationLineItem`, and `FolioEntry`.

Navigation shows every entry. Each page, query, and mutation checks its own permission.
