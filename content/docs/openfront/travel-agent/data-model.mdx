The schema has 37 lists in `features/keystone/models`. `schema.graphql` and `schema.prisma` in the repository are the reference for a revision.

## Rules

- Money is whole cents with a currency code. Rates are basis points.
- Every list has `createdAt` and `updatedAt`.
- Status fields cannot be written by a raw create or update. They change through custom mutations that check the current state, then write an `AuditEvent`.
- Customer-visible codes (`tripNumber`, invoice `number`) are random, never sequential.
- Link tokens are random and stored only as SHA-256 hashes.
- Paid records keep a snapshot of what was bought. An invoice line stores description, amount, quantity, fees, and tax. A booked component stores a purchase snapshot. An accepted proposal stores a snapshot and its hash.

## Computed fields

- `Trip.totalSellCents`, `collectedCents`, `balanceDueCents`, and `expectedCommissionCents`. Cancelled components are left out. Balance counts only the planning fee and `agency_collects` components.
- `Client.lifetimeValueCents`: the sum collected on the client's invoices.

## Append-only and protected

- `AuditEvent`, `ClientFundsEntry`, `AdvisorCommissionLedger`, `CommissionReceipt`, `CommissionAllocation`, `SupplierPayment`, invoices, and payments are never created or edited through the generic API.
- `ManagerApproval` cannot be created or updated through the generic API either.
- Traveler date of birth, passport expiry, and known traveler number cannot be read through the generic API.
- Deleting is closed on every agency list.
