There is no hosted deployment of this product. The repository is private and runs in development. Card payments use Stripe test keys. Moving to live payments is a separate decision that this page does not cover.

## Build and start

`npm run build` runs `keystone build --no-ui`, then `npm run migrate`, then `next build`. `npm start` runs `next start`.

```bash
npm run build
npm start
```

Because the build step migrates, point `DATABASE_URL` at the database you mean to change before you build.

## Checklist

1. Provision PostgreSQL and back it up.
2. Set `DATABASE_URL`, `SESSION_SECRET`, and `PUBLIC_SIGNUPS_ALLOWED=false`.
3. Set the Stripe keys. Use test keys until you have decided how to take live payments.
4. Build, then start.
5. Create the first user at `/dashboard/init`.
6. Run onboarding, or enter your own data.

All app processes must share the same database and `SESSION_SECRET`.

## Railway file

The repository carries the starter's `railway.toml`. It builds with `keystone build --no-ui && next build` and starts with `npm run migrate && next start`, so migrations run on each start. No Railway project or service exists for this product. Deploys are on hold, so treat the file as a starting point and not as a finished setup.

## Not in the repository

There is no worker and no Stripe webhook route. The storefront is a placeholder pending a design.
