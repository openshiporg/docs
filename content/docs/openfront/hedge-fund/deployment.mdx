The repository includes `railway.toml`. The build runs `keystone build --no-ui && next build`, and the start command runs migrations first.

## Processes

| Process | Command | Purpose |
| --- | --- | --- |
| Web | `npm run migrate && next start` | Applies migrations, then serves the dashboard, the fund home page, the API and MCP. |
| Worker (optional) | `npm run worker` | Runs the background jobs: `orders.route` every 5 seconds, `fills.book` every 30, `controls.expire` every 60 and `risk.snapshot` every 300. Each job holds the lease `job:<kind>`, so any number of copies can run. `npm run worker -- --once` runs one tick. |

## Checklist

1. Provision PostgreSQL and set `DATABASE_URL`.
2. Set `SESSION_SECRET` and `PII_ENCRYPTION_KEY`.
3. Deploy, open `/dashboard/init` and create the first admin.
4. Connect a broker under **Brokers** and have a second person approve binding its account.

The included `railway.toml` runs only the web process. Without the worker, orders still route when they are proposed, cancelled or approved and when the **Orders** page loads (`refreshOrders`), but fills are not booked, arming does not expire and daily risk is not snapshotted on a schedule. Run the worker as a second service to get those on a timer.
