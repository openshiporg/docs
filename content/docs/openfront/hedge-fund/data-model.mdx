| Area | Lists |

## Lifecycles

| List | Statuses |
| --- | --- |
| `StrategyVersion.stage` | `draft`, `sealed`, `backtested`, `paper_validated`, `live_approved`, `retired`, `rejected` |
| `Promotion` | `requested`, `evidence_checked`, `approved`, `rejected`, `effective`, `withdrawn` |
| `OrderProposal` | `proposed`, `checked`, `approved`, `rejected`, `expired`, `converted` |
| `Order` | `new`, `working`, `partially_filled`, `filled`, `cancelled`, `rejected`, `expired` |
| `BrokerOrder` | `pending_send`, `sent`, `unknown`, `accepted`, `partially_filled`, `filled`, `pending_cancel`, `cancelled`, `pending_replace`, `replaced`, `rejected`, `expired`, `blocked_halted`, `shadow_recorded` |
| `ControlState.state` | `halted`, `armed` |
| `Breach` | `open`, `acknowledged`, `cured`, `waived` |
| `NavRun` | `draft`, `inputs_locked`, `priced`, `accrued`, `fees_calculated`, `allocated`, `reviewed`, `admin_tied`, `finalised`, `published`, `superseded` |
| `Journal` | `draft`, `posted`, `reversed` |
| `AccountingPeriod` | `open`, `soft_closed`, `locked` |
| `Investor` | `prospect`, `onboarding`, `active`, `restricted`, `offboarded` |
| `Subscription` | `draft`, `submitted`, `docs_complete`, `eligibility_passed`, `screening_clear`, `funds_pending`, `funds_received`, `accepted`, `partially_accepted`, `priced`, `units_issued`, `rejected`, `withdrawn` |
| `Redemption` | `requested`, `notice_validated`, `lockup_checked`, `queued_for_dealing`, `gated`, `priced`, `payable`, `paid`, `holdback_released`, `rejected`, `withdrawn`, `suspended` |
| `PaymentInstruction` | `draft`, `approved`, `sent`, `confirmed`, `failed`, `cancelled` |
| `MarketingReview` | `draft`, `submitted`, `approved`, `changes_requested`, `published`, `withdrawn` |
| `Incident` | `open`, `contained`, `assessed`, `notified`, `closed` |
| `ApprovalRequest` | `pending`, `approved`, `rejected`, `expired`, `cancelled` |

Status fields cannot be updated through the generic API. Only the named mutations move them, and each move writes an audit event.
