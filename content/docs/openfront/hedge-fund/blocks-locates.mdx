A block order is one order across several sleeves, with the allocation fixed before routing. Changing it after the fact is an exception that needs approval. Short sales need a locate. A trade error is identified, assessed, corrected, reimbursed and closed.

## Pages

| Page | Route | What it shows |
| --- | --- | --- |
| Block orders | `/dashboard/platform/blocks` | One order across several sleeves, allocation fixed before routing. |
| Locates and errors | `/dashboard/platform/locates` | Short-sale locates and trade errors. |

## Lifecycles

| List | Statuses |
| --- | --- |
| `AllocationInstruction` | `fixed`, `applied`, `exception_requested`, `exception_approved`, `reapplied` |
| `Locate` | `active`, `used`, `expired` |
| `TradeError` | `identified`, `assessed`, `corrected`, `reimbursed`, `closed` |

## Commands

Named mutations for this area. Each checks permissions on the server, takes an idempotency key and writes an audit event.

`proposeBlockOrder`, `changeBlockAllocation`, `recordLocate`, `reportTradeError`, `assessTradeError`, `correctTradeError`, `requestTradeErrorClose`.
