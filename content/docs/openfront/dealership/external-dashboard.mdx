title: External dashboards
description: Give an LLM the Dealership dashboard skill to adapt the built-in experience or create a separate client.
---

To create a custom Dealership dashboard, copy the skill and give it to your LLM. The skill will explain how `features/dashboard` supplies the Keystone administration shell while `features/platform` contains Dealership's product-specific operator experience.

After that source orientation, it will ask what you dislike, what should stay, what workflows and users matter, and what the replacement should look and feel like. It then traces the exact routes, feature slices, GraphQL calls, schema, access rules, sessions, and provider boundaries in the supplied Dealership codebase before proposing work.

Skill file: [`/skills/openfront-dealership-custom-dashboard/SKILL.md`](/skills/openfront-dealership-custom-dashboard/SKILL.md)

## Current platform pages

Route files are thin wrappers at `app/dashboard/(admin)/platform/<route>/page.tsx`. Logic lives in `features/platform/<slice>`. Navigation is defined in `features/platform/lib/navigation.ts`.

| Page | Slice | What operators do there | Main operations |

| `/dashboard/platform/vehicles` | `vehicles` | Inventory desk: intake, location moves, costs, recon, listing edits, photos, merchandising submit and approve, frontline, publish feed | `inventoryWorkspace`, `intakeInventoryVehicle`, `moveInventoryStock`, `recordInventoryCost`, `openInventoryReconWorkItem`, `transitionInventoryReconWorkItem`, `updateInventoryMerchandisingDraft`, `submitInventoryMerchandising`, `decideInventoryMerchandising`, `transitionInventoryAcquisition`, `recordInventoryFeedRun`, photo commands |

| `/dashboard/platform/vehicles/feed` | `vehicles` | Feed run history | `recordInventoryFeedRun` |
| `/dashboard/platform/deals` | `deals` | Deal list | `dealDeskWorkspace` |

| `/dashboard/platform/users` | `users` | Staff accounts (shoppers are excluded) | Generic `User` CRUD |
| `/dashboard/platform/organization` | `organization` | Tabs: dealer group, rooftops, access (memberships and their audit log), roles, retention | `changeDealerMembership`, `configureRetentionPolicy`, generic `DealerGroup`, `Rooftop`, `Role`, `User` CRUD |

| `/dashboard/platform/reports` | `reports` | Tabs: saved reports, runs (with download), audit search, outbox health | `saveOperationalReport`, `runSavedReport`, `queueDueSavedReports`, `auditSearch`, `DomainOutboxEvent` reads |
| `/dashboard/platform/api-keys` | `api-keys` | Create, scope, limit by IP, and revoke your own API keys | Generic `ApiKey` CRUD |

Onboarding is a dialog in the dashboard layout, not a route. Every list is also reachable on the generic `/dashboard/<list-key>` pages, subject to its access rules. Command-only lists are read-only there.
